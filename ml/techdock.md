# PRIME demo-3 — автономная серверная поставка в ml

Фактическое состояние от **30.09.2026**, после сценарной проверки редакции 1.1 и упаковки. Поставка: `C:\Users\user\Desktop\medhub-app\medhub-app\ml`. Это процедурный локальный сервис для вымышленных анкет, без GUI. `demo=true`, `medical_validated=false` во всех расчётах. Программные тесты не подтверждают медицинскую корректность или готовность к реальным пациентам.

## Назначение и границы

Первый этап рекомендует возрастной пресет PRIME с половой частью и объясняет отдельные скрининги. Второй принимает окончательный выбор пользователя, проверяет ограничения, строит порядок действий и ищет демослоты. Можно убрать рекомендованную услугу и добавить услугу другого PRIME-пакета; причины исходной рекомендации сохраняются. Расписание не вправе сокращать выбранный состав или длительность ради успеха.

Сохранены нормализация, unknown/provenance, процедурные правила, поиск с возвратом, независимый валидатор и бизнес-данные карты. Нет ML/LLM/AI API, БД, сессий, авторизации, реальных пациентов, бронирования, отправки уведомлений, фоновых задач и расчёта стоимости индивидуального набора. HTML-тестер, шаблоны, CSS/JS, изображения и frontend общего репозитория не включены. Swagger/OpenAPI доступны. Подключение существующего frontend ещё требуется отдельно.

## Путь данных и публичные интерфейсы

`patient/context → normalize_input → recommend_base → recommend → окончательный выбор → повторная серверная проверка → plan_actions → schedule_visit + validate_schedule → health_card/next_visit`.

Основные Python-функции из папки ml:

```python
from prime_checkup.selection import recommend_request, plan_request, response_http_status
from prime_checkup.selection import recommend, plan_selection
from prime_checkup.compat import predict
from prime_checkup.cards import get_completed_case
from prime_checkup.scheduler import schedule_visit, validate_schedule
```

`recommend_request(raw)` и `plan_request(raw)` принимают публичные JSON-объекты и возвращают dict. `recommend(patient, context=None)` и `plan_selection(patient, selection, context=None)` используют тот же движок; необязательная инъекция catalog/rules/slots предназначена для технических проверок, не для HTTP-клиента. `predict(patient)` вызывает общий build_plan, без replay-cache. Импорты не запускают сервер, тесты или сеть. Из корня общего репозитория применяется namespace `ml.prime_checkup`; тонкий `from ml import predict` также работает.

| HTTP | Поведение |
|---|---|
| POST /recommend | `{patient, context}` → package/items, catalog/package_options, screening и причины; поиск слотов не вызывается |
| POST /plan | patient/context плюс mode, base_package_id, variant_id, selected_procedure_ids, catalog_version → окончательный состав, изменения, порядок, расписание, карта |
| POST /predict | Совместимая автоматическая обработка самого объекта анкеты |
| GET /health | Только standalone; router не добавляет служебный маршрут в приложение владельца |

Все форматы, ошибки и полные рабочие JSON: [CONTRACT.md](docs/CONTRACT.md). В документации одна каноническая схема; исторический remote CONTRACT не подменяет её. Полный [пример рекомендации](docs/recommend-request.json) получает basic/male, 14 услуг; [пресет](docs/preset-request.json) даёт feasible. [Custom](docs/plan-request.json) исключает prime_lipids_glucose_group и добавляет prime_hepatitis_bc_group; с этими слотами получается ready/infeasible, весь выбор сохранён. [Пустой массив](docs/empty-request.json) даёт needs_input. Ответы записаны рядом и сверены через настоящий HTTP целиком.

## Анкета и ограничения

Поддерживаются четыре явных формата: current `clinic_v2` (30 вопросов снимка 744d7f7), сохранённый `clinic_v1`, импорт `df733c4` с потерями старого экспорта и короткий технический `legacy` с age. Наличие birth_date/birth_year без версии по-прежнему выбирает старый импорт: нынешний клиент обязан указывать clinic_v2. Таблица полей и влияния — [INPUT_CONTRACT.md](docs/INPUT_CONTRACT.md).

Возраст PRIME — полные годы `age_full` на as_of_date. Возраст скринингов — `age_year=checkup_year-birth_year`. Фиксированные демо-defaults: 2026-09-30 / 2026 / визит 2026-10-01 / availability=normal. Они возвращаются в context/input_context; текущая дата не участвует в расчёте. Возраст 0 и взрослый for_child=true не обходят границы детского пакета.

Отрицание, unknown, пропуск и неприменимость различаются. current registered независим от conditions; производный старый диагноз остаётся наблюдением об экспорте. hazardous_work_10y=false не превращается в true. Пропущенный компонент курения не становится 0; явно сообщённый 0 сохраняется. H0 — never по каждому screening_id; действительный 2025 остаётся годом, старый YEAR−1 из ответа о последних двух годах — диапазоном. История не создаёт результата обследования.

Сначала проверяется формат, затем urgent. Известная остановка на обоих этапах возвращает review, package=null, route=[], schedule.not_run. Отсутствующий/unknown urgent — needs_input с теми же пустыми пакетом/маршрутом. `other_now` принадлежит прежним форматам; current его не содержит. Независимое глобальное условие нельзя обойти прямым /plan или снятием checkbox.

КТ/маммография при беременности/неуверенности либо отсутствующем применимом ответе требуют решения. Ограничения связаны с ID/тегами; хеликобактер не получает ложный тег. Условные услуги и неизвестная применимость не выдаются за согласованные. Выбранная эндоскопическая группа при blood_thinners=yes или companion=no сохраняет S19 review/not_run и вопросы о подготовке. Нет схем отмены препарата. Удаление конкретной услуги снимает только её локальную блокировку.

## Выбор, порядок и расписание

Каталог содержит **43** выбираемые услуги/группы. Варианты: basic female/male — 16/14, extended female/male — 15/15, child mini/extended — 8/5 исходных позиций. Это не число атомарных анализов. Нераскрытые группы не разворачиваются в выдуманные исследования. Куратор остаётся одной услугой с двумя стабильными action_id; итоговое действие — after_results. Мужской уролог не заменяется женским draft-ID. Точная карта исходная строка → procedure_id → action_id сохранена в [сценарном наборе](tests/fixtures/prime_scenarios.json) и миграции каталога.

В preset сервер восстанавливает конкретный допустимый вариант. Несовпадающий присланный список — 422 preset_mismatch. В custom массив обязателен: отсутствует → 422 missing, [] → needs_input без отката, неизвестный/screening ID → 422, повторные ID детерминированно объединяются. Устаревший catalog_version → 409 catalog_changed. Сервер повторно рассчитывает ограничения; клиентские статусы/названия/длительности не являются источником истины.

added_items/removed_recommended_items сравниваются с автоматической рекомендацией для анкеты. Отказ не запрещён и сам по себе не требует согласования. Сохраняются исходное why и предупреждение. Ручное добавление имеет пользовательское основание. Индивидуальный набор: total_price=null, «Стоимость — у администратора»; никаких скидок или предполагаемой оплаты из скринингов.

Порядок day_route_order строится между выбранными действиями. Сортировка по ID разрешает равенство, не создаёт лишнюю медицинскую предпосылку. Отсутствующая явная обязательная предпосылка даёт review без скрытого добавления. route — проект порядка либо фактическая хронология feasible-расписания; часы находятся в schedule. У review отдельной услуги допустим только draft, schedule.not_run; urgent не получает проекта.

Поиск с возвратом использует конечные слоты [start,end), целые минуты, начало строго slot[0], фактическую длительность, независимую занятость пациента/ресурсов и зависимости. Готовый результат проходит отдельный validate_schedule. Исчерпывающий неуспех — infeasible, лимит — unknown, недостающая техническая информация — needs_data, повреждённые данные — invalid/422. Ничего не исключается ради успешного маршрута. Серверные prime_slots задают тестовый день 09:00–17:00 и буфер 0; busy меняет доступность. Это демонстрация размещения, не клинически проверенный маршрут или запись.

## Скрининги, карта и следующий визит

Семь предоставленных screening-правил возвращаются отдельно как candidate/not_eligible/needs_input/review с причиной, источником, недостающими данными, payment и where. При unknown прикрепления — уточнение поликлиники. Кандидатность не подтверждает оплату/доступность. exact/partial/unknown-связи с PRIME не удаляют выбранные услуги и не скрывают клинические ограничения. Неопределённость только скрининга не блокирует PRIME.

20 ANAMNESIS_DRAFT-правил не активированы: S18 частично OUT_OF_SCOPE. Анамнез/лекарства/сопровождающий передаются врачу без назначения по свободному тексту. Конфликт границы 15 лет отказа от курения остаётся review, медицинский оператор не выбран догадкой.

Плановая health_card отражает только окончательно выбранные услуги: «не пройдено», «нет данных». next_visit — массив, обычный элемент results_review имеет date/year/basis=null, requires_clinician и причину назначения после готовности результатов и решения врача. reminder_draft без даты, sent=false. Для реальной даты нужен источник правила/назначения; интервал скрининга не становится личным назначением.

`cards.get_completed_case()` возвращает независимую копию waiting/received/reviewed; неизвестное имя отклоняется до чтения файла. Сохранены три вымышленных состояния, история «Маммография — 2025 год, результат/проверка неизвестны» и фиксированный срок 2026-10-15 только в reviewed fixture. История, выполненность, получение результата, просмотр врача и следующее действие различаются. Анкета не изменяет эти данные. HTML-страницы карты не перенесены.
