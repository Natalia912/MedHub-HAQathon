# Конструктор чекапа — на чём строить (для Даниила)

Принцип: **каждое правило — строка в таблице, у каждой рекомендации есть источник.** Движок только читает таблицу,
логики «если-то» в коде минимум. Модель обучать не нужно.

## Три слоя правил

### Слой 1. Какой пакет PRIME — источник: сайт клиники (`prime_checkup_packages.md`)
- 1–17 лет → «Детский» (мини / расширенный)
- до 40 лет → «Базовый»
- 40+ → «Расширенный»
- по полу добавляются женская (маммография, ПАП-тест, УЗИ малого таза) или мужская (ПСА, ТРУЗИ) часть

### Слой 2. Что положено бесплатно — источник: приказ МЗ РК ҚР ДСМ-174/2020, прил. 1–2 (`normativ/`)
- Условие: пол + **ГОД ДОСТИЖЕНИЯ** возраста (40, 42, 44… ; для шейки матки 30, 34, 38…) + НЕ состоит на учёте по этому заболеванию
- Результат: метка «бесплатно — скрининг», объём 1-го этапа, кто платит (ГОБМП / ОСМС), периодичность (2 или 4 года), срок завершения 60 дней
- На учёте по заболеванию → скрининг НЕ положен → «к вашему врачу по наблюдению» (прямо в приказе)

### Слой 3. Жалобы и анамнез — ⚠ нормативной опоры нет
- Пример: рак кишечника у родственника → колоноскопия раньше 50; усталость → акцент на B12, D, ТТГ (уже в пакете)
- Источник у таких правил: **«правило клиники — требует подтверждения врача»**, на экране — с этой пометкой
- Для демо 3–5 правил, не больше. Не выдавать за медицинскую норму.

## Служебные блоки
- **Маршрут на 1 день:** анализы натощак → УЗИ / функциональная диагностика → КТ → консультации → эндоскопия под наркозом последней (гастро + колоно вместе). Пометка «порядок — уточнить у клиники».
- **Напоминание о повторе:** из периодичности приказа (2 / 4 года); для платного пакета — «через год, по рекомендации клиники».

## Формат правила
```json
{
  "id": "scr_breast",
  "layer": "screening",
  "when": {"sex": "F", "age_year": [40,42,44,46,48,50,52,54,56,58,60,62,64,66,68,70,72,74,76], "not_registered": "Z12.3"},
  "exam": "Маммография (4 снимка)",
  "payment": "free_gobmp",
  "repeat_years": 2,
  "deadline_days": 60,
  "source": "Приказ МЗ РК ҚР ДСМ-174/2020, прил. 1 п.3, прил. 2 п.2"
}
```
`payment`: `free_gobmp` | `free_osms` | `paid_prime`. Движок собирает сработавшие правила → в ответ `predict()`,
в поле `reasons` пишем «обследование — почему — источник» (поле уже есть в `contract/predict_contract.py`).

## Возраст — по ГОДУ достижения
`age_year = текущий_год − год_рождения` (не полных лет!). Человек, которому 40 исполнится в декабре, скринингуется в этом году.

## Что ещё по профилю Даниила
1. **Тесты:** 20–30 синтетических пациентов (пол, возраст, учёт) + ожидаемый ответ → прогон через движок. Защита от ошибки на демо.
2. **Прогноз нагрузки скрининга по месяцам:** сколько прикреплённых попадает в целевые группы по году возраста и как разложить поток по месяцам (снимаем очереди). На демо — один график «было / стало» на синтетике, если успеем.
