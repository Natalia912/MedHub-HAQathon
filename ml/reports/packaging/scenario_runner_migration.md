# Перенос сценарного прогона в автономный пакет

Команда из папки `ml`:

```powershell
python -m tools.run_scenarios
```

Для отдельного результата проверки копии:

```powershell
python -m tools.run_scenarios --phase copied-folder --output scenario_copy_results.json
```

Новые результаты записываются только в `reports/packaging`. Имя `--output` должно начинаться с `scenario` и заканчиваться `.json`; путь к другой папке не принимается. Исторические `reports/scenarios/*`, исходный DOCX, закреплённый fixture и его две документированные поправки остаются неизменными. До и после прогона runner сверяет контрольные суммы всех исторических файлов.

Перенесены исходный `StateRun`, все специализированные проверки, 124 утверждения документа и шесть сравнений между состояниями. `StateRun` отличается только путями двух точек перехвата вызова планировщика: `prime_checkup.*` вместо `app.*`. Это проверено сравнением AST; `scenario_assertions.py` совпадает с исходным файлом побайтно. Проверки AST и SHA fixture сохранены в `scenario_runner_migration_checks.json`.

Используются 48 состояний: 46 пар запросов `/recommend` и `/plan` через FastAPI TestClient и два изолированных fixture S25 через прежний планировщик. Отдельно вызывается `/health`. HTML-проверки исходного приложения не входят в автономный JSON-пакет и не запускаются этой командой. TestClient не означает запуск Uvicorn или визуальную проверку браузером.

Добавлена точная сверка с `reports/scenarios/results.json:final`: полностью сравниваются все 92 запроса/ответа HTTP, 46 результатов нормализации, ошибки нормализации, перехваченные входы планировщика, оба результата S25 и наборы проверок. Внутри бизнес-результатов нет исключённых полей. Отличающиеся технические время прогона и manifest не используются как медицинский результат.

Все зависимости загружаются из текущего пакета `prime_checkup`; runner не импортирует прежний `app`, не изменяет `sys.path`, не обращается к прежнему рабочему каталогу и не требует Git. Файлы данных читаются относительно расположения пакета и инструментов.

Первый новый полный прогон выполнен из целевой папки `ml` с интерпретатором существующего виртуального окружения; код и данные загружены из нового пакета. Это не проверка отдельной чистой установки. Фактический результат сохранён в `scenario_results.json`:

- 48 состояний: 47 PASS, одно PARTIAL_SCOPE — неактивное предложение ANAMNESIS_DRAFT в S18.
- 92 сценарных POST-запроса, один GET `/health`, два прямых вызова прежнего планировщика для S25.
- 2354 проверки: 2353 PASS, одна OUT_OF_SCOPE; FAIL, BLOCKED и NOT_RUN — ноль.
- 124 утверждения DOCX: 121 PASS, три OUT_OF_SCOPE; шесть сравнений между состояниями — PASS.
- 338 точных сравнений с историческим прогоном — PASS. Изменений бизнес-ответов, нормализации, fixture, проверки маршрутов или ожидаемых данных нет.
- Контрольные суммы всех сохранённых исторических файлов до и после нового прогона совпали.

Прогон проверяет сохранение реализации при переносе и заданные синтетические свойства. Он не подтверждает медицинскую корректность или возможность реальной записи.
