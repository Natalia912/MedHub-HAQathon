## Почему альтернативные реализации не перенесены

| Дерево | Статически подтверждённое поведение |
| --- | --- |
| main | Только `GET /`, `/health`, `/fields`; локального двухэтапного движка здесь нет. |
| engine | `ml/router.py` объявляет `/recommend` и `/plan`, но не подключён к main. Plan использует названия услуг, строит маршрут после red_flags; пакет выбирает по календарному возрасту, пропуски курения превращает в 0, будущий повтор считает от checkup_year, активирует draft-добавления. |
| packages-logic | Подключает другой `POST /recommendations` через `app/recommendations.py`. Пакет выбирает по календарному возрасту. Беременность автоматически исключает строки по подстроке «кт», затрагивая хеликобактер. В items смешиваются PRIME, скрининги и draft-добавления. `app/itinerary.py` строит иллюстративные часы и кабинеты по текстовым категориям; это другой механизм, без поиска слотов и независимого валидатора demo-3. |

Эти модули только прочитаны; не импортированы, не запускались и не скопированы в пакет. Их тесты не используются как эталон. Согласованные два этапа, полные годы для PRIME, unknown/provenance, окончательный пользовательский выбор, отдельные скрининги, review/not_run и следующий визит без выдуманной даты остаются приоритетом локальной реализации. Удалённые CONTRACT/README сохранены как исторические источники, не как новое API упаковки.

Current-анкета содержит независимый `registered`, прямые вложенные `smoking`, годовую историю и шесть `yes/no/unsure`. Её `collectInput` сохраняет явные false/0, но опускает пустые массивы. Пропуск не восстанавливается как «нет». Сохраняется известный конфликт источника скрининга лёгких: `quit_years_max=15` против «менее 15 лет» в note; упаковка не разрешает этот медицинский вопрос.

## Сохранность и готовность к Git

До и после сверки совпали HEAD, `git status --porcelain` и SHA-256 **190 файлов исходной рабочей копии**: изменённых путей нет. Fetch изменил только разрешённые remote-tracking metadata. Доказательства: [source_git_before.json](source_git_before.json), [source_git_after.json](source_git_after.json), [source_audit.json](source_audit.json).

Родитель целевой папки — каталог из ZIP, **не Git checkout**. Здесь нельзя честно заявить готовность коммита или успешный `git check-ignore` относительно будущего репозитория. В исходном и целевом корневом `.gitignore` есть `ml/data/`: при интеграции нужно проверить исключения для синтетических JSON и выполнить `git check-ignore`/`git status` в настоящем checkout. Коммит, push и изменение корневого `.gitignore` этой сверкой не выполнялись.

Сохранены только JSON/Markdown источников и извлечённые метаданные вопросов. HTML, CSS, JavaScript, изображения и альтернативные исполняемые модули не копировались. Для прочитанного кода сохранены URL, Git blob ID, размер и SHA-256. Сырые правила в `snapshots/` — архивное доказательство, не активный runtime-каталог. Тестовые результаты упаковки записываются отдельным отчётом; эта сверка не объявляет медицинскую валидацию или готовность к реальным пациентам.
