# PRIME: поля и нормализация анкеты

**Публичный контракт новых клиентов: [CONTRACT.md](CONTRACT.md), версия от 30.09.2026.** Этот документ сохраняет актуальную таблицу полей анкеты, происхождение значений и правила нормализации. Анкета обрабатывается одним адаптером [prime_checkup/intake.py](../prime_checkup/intake.py); функции `recommend()` и `plan_selection()` в [prime_checkup/selection.py](../prime_checkup/selection.py) используют общую процедурную логику [prime_checkup/engine.py](../prime_checkup/engine.py). Совместимый `build_plan()` остаётся автоматическим расчётом для `/predict`, а не новым двухэтапным клиентским контрактом. Источник вопросов и данных — снимок `df733c43d5ab655ef08036366a44bae04e59182f`, сохранённый в [reference/df733c4/](../reference/df733c4/).

Это локальный тестер вымышленных анкет: `demo=true`, `medical_validated=false`. По сообщению пользователя вопросы проверены акушером. Это происхождение предоставленной анкеты, а не подтверждение алгоритма, медицинских назначений или расписания; имя врача и более широкое одобрение не предполагаются.

## HTTP и выбор формата

`POST /recommend` принимает JSON с `patient` и `context`, возвращает рекомендацию и каталог без поиска слотов. `POST /plan` принимает JSON с той же анкетой, контекстом и выбором пользователя. HTML-формы используют отдельные `POST /tester/recommend` и `POST /tester/plan`, вызывающие те же функции. `POST /predict` принимает исходную анкету в совместимом автоматическом режиме; его прежний HTML-вариант перенесён на `/tester/legacy-plan`. Ошибки структуры дают HTTP 422 и `status=invalid`; устаревшая версия каталога — HTTP 409 `catalog_changed`; бизнес-исходы `ready/needs_input/review`, включая невозможность расписания, — HTTP 200. Схема выбора и ответов определена в [двухэтапном контракте](CONTRACT.md).

| `input_version` | Назначение |
| --- | --- |
| `legacy` | Прежние семь полей короткого технического профиля; новые медицинские ответы не предполагаются |
| `clinic_v1` | Явные ответы новой локальной анкеты с сохранением отрицательных и неизвестных значений |
| `clinic_v2` | Самостоятельные ответы 30 полей снимка `744d7f7`: отдельные диагнозы на учёте, вложенные сообщённые значения курения и годовая история |
| `df733c4` | Совместимость с девятью исходными input и старой `collectInput()`, теряющей часть ответов |

Без версии наличие `birth_date` или `birth_year` выбирает df733c4, иначе наличие `age` — legacy, иначе — clinic_v1. Последнее позволяет обработать единственный ответ urgent. Для current-анкеты снимка `744d7f7` следует явно передавать **clinic_v2**: автоматический fallback не меняется и не превращает старый экспорт в новый факт. Смешение `age` и нового формата, неизвестная версия, несовместимые типы и лишние поля отклоняются; `extra=ignore` не используется. Существующая локальная HTML-анкета остаётся clinic_v1; её перенос на удалённые 30 полей не выполнялся.

### Current 744d7f7: минимальное расширение адаптера

Версия `clinic_v2` добавлена после исходного прогона сценариев. `input_context.source_sha=744d7f79e6872a31572dda9d75269a8a8b7bcd4a`, `adapter_version=intake-2`; SHA каталога возвращается отдельно в `versions.source_sha`. Поля и ограничения прежних `clinic_v1`, `df733c4` и короткого `legacy` сохраняются, кроме явно исправленного вывода отрицания учёта из широкого `conditions=["none"]`.

| Поле / техническое состояние | Передача и смысл |
| --- | --- |
| `urgent` | none/chest_pain/dyspnea/stroke_signs; unknown или отсутствие требуют ответа до пакета. other_now поддержан только в прежних форматах |
| `registered` | Отдельный список точных кодов, не выводимый из conditions. `provenance.registered="confirmed_clinician"` обозначает отдельно сообщённое подтверждение в синтетическом профиле, а не проверку личности врача |
| `registered_absent` | Дополнительный список конкретных явно отрицаемых кодов учёта; например, девять отрицаний рядом с неоднозначным breast_cancer старого экспорта. `provenance.registered_absent="patient_reported"`; нормализуется в `registration.negative_codes`, не в подтверждённые диагнозы |
| `smoking` | `{ "pack_years": 25, "quit_years_ago": 0 }` — два непосредственно сообщённых числа. Любое отсутствующее число остаётся null; статус курения не выдумывается (`reported_exposure`). Пропущенный срок при pack_years=25 не равен 0. Старые smoke_status/cigs_per_day/smoke_years/верхний quit_years_ago не смешиваются с clinic_v2 |
| `last_screening` | Объект по любому из семи screening_id. Значение — настоящий год, `"never"`, `"unknown"` или null. H0 передаётся семью отдельными `"never"`; пустой объект не означает «никогда» |
| История `never` | `performed_status="never"`, `date_precision="not_applicable"`, обе даты null, результат/просмотр unknown. История сохраняется независимо от пола и возраста, включая ребёнка; это факт прошлого, не предложение скрининга |
| `risk_group` | Список кодов, отдельные `["none"]`/`["unknown"]` либо объект `{код: "yes"/"no"/"unknown"/"unsure"}` для частично известных ответов. Только контекст врачу: семь активных screening.when не используют это поле |
| Шесть select | discharge, dysuria, anesthesia_reaction, blood_thinners, allergy, companion принимают yes/no/unsure. unsure сохраняется исходным значением со state=unknown; это не no. Прежний технический unknown тоже поддержан |
| Применимость | discharge — взрослая женская ветка, dysuria — взрослая мужская. У ребёнка не предполагаются курение/профриск/репродуктивные ответы. Явные ответы anesthesia_reaction/blood_thinners/companion ребёнка сохраняются для врача. hazardous_work_10y у взрослого не теряется из-за старого UI-ограничения 50–70 лет |
| Другой контекст и даты | В clinic_v2 conditions_other сохраняется врачу даже при conditions=["none"]: список не исчерпывает свободный текст. Правила из него не создаются. last_period раньше birth_date даёт 422 как невозможная последовательность дат, без медицинской интерпретации |

Коды `risk_group`: medical_worker_invasive, planned_surgery, hemodialysis_oncology_hematology, transfusion_transplant, pregnancy, hiv_key_population. Поле не включает прежние draft-назначения. Для S10 допустимо `{"pregnancy":"unknown","medical_worker_invasive":"no","planned_surgery":"no","hemodialysis_oncology_hematology":"no","transfusion_transplant":"no","hiv_key_population":"no"}`.

Технические `registered_absent`, per-ID `never/unknown` и частичный risk_group разрешены также вместе с df733c4 для явно сообщённых дополнительных фактов. Они не повышают доверие к производному зарегистрированному диагнозу и не меняют старое происхождение smoking. Противоречие между кодом учёта и его явным отрицанием даёт 422. Явный `quit_years_ago=0` старой записи «курит сейчас» сохраняется; отсутствие либо производный nested 0 не подставляются вместо него.

В clinic_v2 отсутствие истории конкретной применимой программы и явный неизвестный ответ дают needs_input только в её информационном результате, с полем `last_screening.<screening_id>`. Явный `never` является достаточным ответом об отсутствии прошлого прохождения. PRIME не блокируется, срок повтора не назначается. Для совместимости clinic_v1/df733c4 отсутствие истории сохраняет прежнюю формальную candidate с ограничением «фактическая периодичность не установлена»; такая candidate не подтверждает интервал, оплату или назначение.

`conditions=["none"]` больше **не** устанавливает отсутствие динамического наблюдения ни в одном формате расширенной анкеты. Для отрицательного ответа нужен `registered=["none"]` либо соответствующие конкретные `registered_absent`. Старый явный registered_on=["none"] по-прежнему сохраняет свой смысл. Широкое состояние, производный код и отдельно подтверждённый диагноз остаются разными фактами.

На границе `age_full=17`, `age_year=18` информационное правило scr_hepatitis возвращает review с вопросом о применении нижней границы до дня рождения. Это локализация неоднозначности источника, а не новая медицинская возрастная граница и не блокировка PRIME.

HTML-поля `smoking_json`, `last_screening_json`, `provenance_json` — только транспортный редактор вложенных объектов. API принимает `smoking`, `last_screening`, `provenance`. Два представления истории одновременно не допускаются.

### Пример новой анкеты

Ниже показан объект `patient`; в новых запросах его передают внутри оболочки из двухэтапного контракта. Технические настройки можно вынести в `context`.

```json
{
  "input_version": "clinic_v1",
  "for_child": false,
  "sex": "F",
  "birth_date": "1986-12-01",
  "birth_year": 1986,
  "urgent": "none",
  "pregnant": "no",
  "conditions": ["none"],
  "family_history": ["unknown"],
  "smoke_status": "never",
  "as_of_date": "2026-09-30",
  "checkup_year": 2026,
  "visit_date": "2026-10-01",
  "availability": "normal"
}
```

Здесь `age_full=39`, `age_year=40`; возрастной кандидат PRIME — basic. Итоговая готовность состава определяется также остальными правилами. Неопределённость только информационного скрининга не блокирует PRIME.

### Legacy

```json
{
  "input_version": "legacy",
  "age": 35,
  "sex": "F",
  "complaints_state": "none",
  "complaints": [],
  "family_crc": "no",
  "visit_date": "2026-10-01",
  "availability": "normal"
}
```

Все семь полей, кроме версии, обязательны. `age` — строго целое 1–120; дробное число, строка JSON и bool не принимаются. `complaints_state=list` требует хотя бы один код `fatigue/chest_pain`; при `none/unknown` список пуст. `sex`: M/F/unknown; `family_crc`: yes/no/unknown. Известный chest_pain останавливает подбор раньше неизвестного семейного анамнеза. Fatigue только выделяет существующие позиции. В новом формате `complaints`, `complaints_state`, `family_crc` не принимаются: новая анкета их не спрашивает.

## Технический контекст и два возраста

| Поле | Формат / default | Использование |
| --- | --- | --- |
| `as_of_date` | ISO-дата / `2026-09-30` | Оценка полного возраста и проверка будущих дат |
| `checkup_year` | Целое 1–9999 / `2026` | Год достижения возраста для скрининга |
| `visit_date` | ISO-дата / `2026-10-01` | Условный день маршрута, не бронирование |
| `availability` | normal/busy / normal | Только выбор тестовых слотов |
| `input_version` | Четыре версии выше | Схема и происхождение |
| `provenance` | Объект строковых маркеров / `{}` | Дополнительное происхождение, не медицинский ответ |

Движок не читает текущую дату машины. Применённые defaults перечислены в `input_context.defaulted`, значения возвращаются рядом. Девять импортированных примеров используют as_of_date=2026-09-30 и checkup_year=2026.

`age_full` вычисляется по полной дате рождения и as_of_date; `age_year = checkup_year − birth_year`. Один год рождения даёт только age_year: для пакета потребуется полная дата. Одновременно переданные дата и год должны совпадать. Несуществующие/будущие даты, год скрининга до рождения и полный возраст более 120 отклоняются. Возраст 0 допустим как факт, но детский пакет ограничен 1–17. Взрослый с for_child=true требует уточнения, не получает детский пакет.

## Неизвестность, применимость, provenance

`input_context.answers[field]` содержит state, исходное value, source. Состояния: answered, unknown, unanswered, not_applicable. Внутреннее values содержит только применимые значения. После смены пола/возраста/родительского ответа неприменимые значения остаются в метаданных с предупреждением, но не влияют на расчёт. Например, прежний discharge=yes в мужской ветке не создаёт предложения; прежние сроки курения у ребёнка не создают глобальную блокировку. Значимые применимые противоречия требуют уточнения.

В clinic_v1 «нет» и «не знаю» разделены. У df733c4 пропущенный ключ имеет source=df733c4:not_exported: удалённый отрицательный ответ восстановить нельзя. Импортированный family_history=["none"] считается unknown, поскольку исходная подпись объединяла «нет или не знаю».

`provenance.registered="confirmed_clinician"` учитывается только с явным clinic_v1/clinic_v2: точные registered становятся confirmed_codes. При df733c4 даже такой маркер не повышает доверие. Все импортированные registered и преобразованные registered_on остаются ambiguous_codes. Отрицательный ответ отдельно учитывается только при явных согласованных сведениях об учёте, а не по conditions. Маркер происхождения — декларируемые данные тестера, не удостоверение личности врача. Другие строковые provenance сохраняют источник, но не дают произвольного медицинского доверия.

В clinic_v1/df733c4 пачка-лет вычисляются только из полного согласованного исходного smoke_status/cigs_per_day/smoke_years; явное never допускает 0. У текущего курильщика без отдельного ответа срок отказа null; явно сообщённый верхний quit_years_ago=0 сохраняется. При quit пропуск — null, известный 0 — число 0. Несогласованный экспорт smoking, стаж больше возраста или сумма стажа и срока отказа больше возраста дают вопросы внутри smoking и локальный исход скрининга. Они не останавливают PRIME. Производные значения не заменяют исходные ответы, даже при provenance.smoking. В clinic_v2 smoking непосредственно сообщён пациентом, как описано выше; смешение старых и новых представлений отвергается.

`provenance.last_screening="known_year"` сохраняет действительно известный год, включая df733c4. Иначе искусственный checkup_year−1 из экспорта становится диапазоном последних двух лет. Новый список скринингов также означает диапазон. День и месяц не вычисляются. Отдельная история «2025 год» на /demo/completed не перезаписывается.

В clinic_v1/df733c4 видимость hazardous_work_10y сохранена по полному возрасту 50–70. На границе age_full=49, age_year=50 информационное правило может нуждаться в недоступном вопросе. Такая зависимая ветка локализуется как review с объяснением расхождения возрастов, PRIME не блокируется. В clinic_v2 этого ограничения видимости нет; явно сообщённый взрослым ответ сохраняется, а возрастные границы самого скринингового правила не меняются.

## Порядок решения и выход

Ниже описаны общие решения и базовые поля совместимого автоматического ответа `/predict`. В новом API `/recommend` всегда завершает работу до поиска слотов; `/plan` дополнительно возвращает окончательный выбор, добавления/исключения, проект порядка и следующий визит по [CONTRACT.md](CONTRACT.md).

После структурной проверки новый формат первым проверяет urgent. Известное положительное значение возвращает review, package=null, schedule.status=not_run, пустой маршрут. Необязательный анамнез для остановки не требуется. В прежних clinic_v1/df733c4 other_now имеет отдельное сообщение обращения к врачу без универсального автоматического «103»; в clinic_v2 это недопустимый вариант. Отсутствие/unknown urgent даёт needs_input до выбора пакета.

По S19 документа Scenarios.docx 1.1 и исходным prep_catalog.pr_thinners/pr_anesthesia выбранная групповая услуга эндоскопии под анестезией получает локальное review при явно сообщённом blood_thinners=yes или companion=no. До согласования подготовки schedule.status=not_run; выбранная услуга сохраняется. Не назначаются отмена/схема приёма лекарств и не выдаётся допуск к анестезии. После удаления этой услуги снимается только относящаяся к ней блокировка; сведения остаются врачу. Остальной анамнез и лекарства остаются контекстом, 20 ANAMNESIS_DRAFT-правил не включаются.

Затем уточняются полный возраст, пол и значимые противоречия. После выбора допускается расширение прежнего review: package/items могут содержать **предварительный** состав с package.preliminary=true. Это применяется к условным услугам «по показаниям», беременности и неизвестному применимому ответу для зависимых услуг. Расписание not_run; состав не выдаётся за согласованный. Блокирующая urgent-ветка предварительный пакет не показывает.

| Поле ответа | Содержание |
| --- | --- |
| `status` | ready/needs_input/review/invalid; готовность демо-состава |
| `demo`, `medical_validated` | Всегда true, false |
| `package` | Кандидат PRIME, ID, имя, причина, URL, price, preliminary; либо null |
| `items` | ID, имя, источники, причины, validation_status, признаки группы и условности |
| `items[].clinical_flags` | Независимые клинические пометки и уточнения |
| `items[].screening_matches` | Явные screening_id, степень exact/partial/unknown и исход; не оплата |
| `items[].actions` | Связанные действия одной услуги, включая первичного/итогового куратора |
| `input_context` | Версия формата, SHA, defaults, даты, оба возраста, answers, registration, smoking, history |
| `screening` | Исходы с rule_id, outcome, reason, missing_fields, источником и ограничениями |
| `doctor_summary` | Применимые ответы для врача без интерпретации |
| `proposed_extras` | Необязательные предложения обсуждения, scheduled=false |
| `alternatives` | Детский extended отдельно от mini |
| `questions`, `warnings`, `trace` | Уточнения, ограничения, исходы правил |
| `schedule` | feasible/infeasible/unknown/needs_data/not_run, route, after_results, reason |
| `health_card` | Услуги: «не пройдено», «нет данных» |
| `reminder_draft` | Обычный план без назначенной даты, sent=false |
| `versions`, `errors` | Версии; ошибки scope/field/code/message |

Блок называется «Скрининги: что уточнить в поликлинике». candidate — соответствие указанным критериям предоставленного демоправила, не право на бесплатное прохождение. not_eligible/needs_input/review отдельного скрининга не отменяют пакет. Информационный блок сам не удаляет услуги; пользователь может исключить их явно на втором шаге. Цена не пересчитывается, результаты и даты напоминания не генерируются. Известной истинной ветки OR достаточно. На спорной границе отказа от курения в 15 лет возвращается review, когда исход зависит от расхождения текста и JSON.
